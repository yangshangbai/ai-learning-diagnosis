## 一、收敛定义("没有一点BUG"的工程化判据)

绝对零缺陷不可验证,采用**可操作的收敛判据**,全部满足即宣布收敛并交付:

1. 连续 **2 轮**全量遍历**零新增 P0/P1** 缺陷;
2. P0 回归集(46 条)连续 2 轮 **100% 通过**;
3. 全部 P1 缺陷闭环(修复+回归通过);P2/P3 修复或经用户豁免;
4. 核心大闭环(BF8: 导入→组卷→考试→识别→判分→看板)连续 2 轮全通;
5. **产品豁免清单**(已知断链: 反馈页/操作审计/旧Vue SPA)经用户确认签字,不计缺陷;
6. 产出: 总测试报告 + 缺陷台账(全部 CLOSED/豁免)+ 收敛 tag。

未满足 → 继续下一轮(方案预算 8 轮,超出后向用户汇报密度再定)。

## 二、Loop 引擎(状态机)

```
┌─────────────────────────────────────────────────────────┐
│ R.n-A 遍历测试批   [CX-07-QA×2 并行]                      │
│   QA-API: L1 全量接口遍历(本轮焦点模块 P0/P1 全跑)         │
│   QA-UI : L2 Chrome 人手流遍历(本轮焦点页面+操作节点截图)   │
├─────────────────────────────────────────────────────────┤
│ R.n-B 审查批       [CX-03红队 + CX-05架构]                │
│   对 R.n-A 全部缺陷做: 复现确认→分级→设计审查→代码审查      │
│   输出: 修复决策(修/豁免/延期) + 修复方案(每条)             │
├─────────────────────────────────────────────────────────┤
│ R.n-C 修复批       [CX-06-DEV×1~2]                       │
│   按方案修复 → py_compile/JS check → 版本号递增            │
├─────────────────────────────────────────────────────────┤
│ R.n-D 回归部署批   [CX-07-QA×1 + CX-09×1]                │
│   部署云端+重启+冒烟 → 修复项回归 → 受影响面回归 → 全量P0   │
│   → 更新台账/覆盖矩阵/LOOP-STATE → git commit 快照         │
└─────────────────────────────────────────────────────────┘
        ↑ 未收敛: n+1 进入 R(n+1)-A(携带上轮回归集) ┘
```

**时间预算**: 每轮 40-50 分钟(A:15 + B:8 + C:12 + D:10),**7 轮 ≈ 5.2 小时**;轮次焦点轮换保证 5 小时内全量覆盖;R8+ 为收敛机动轮。

**断点续跑**: 每轮结束提交 `LOOP-STATE.md`(当前轮次/焦点/覆盖矩阵进度/台账指针)到 Git——跨会话可从任意断点恢复,不丢进度。

## 四、缺陷台账与审查-修复流

**BUG-LEDGER.md**(唯一真源),每条缺陷: `BUG-nnn | 轮次 | 模块 | 级别P0-P3 | 复现步骤 | 证据(截图/API响应) | 根因 | 设计审查结论 | 代码审查结论 | 修复commit | 回归结果 | 状态(OPEN/FIXED/豁免/延期)`。

流程: QA 登记 → 主Agent 分级确认 → CX-03 设计审查(是否设计缺陷)+CX-05 代码审查(实现缺陷/修复方案)→ 主Agent 决策(修/豁免/延期)→ CX-06/08 实施 → 回归 → 台账闭环。**设计缺陷必须先改文档(01/02/03 号逆源文档)再改代码。**
