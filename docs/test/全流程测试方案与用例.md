# 全流程测试方案与用例集(模拟人手操作·按业务流)

> 版本: v1.0(待用户审批) | 日期: 2026-08-30 | 基线: v2.0.1(`ec6720b`,已部署云端)
> 方法: design 流程 = 用户视角人手操作(浏览器 Chrome) + CLI/API 双轨验证
> 测试对象: http://175.178.29.97 (生产前端 demo SPA + /api/v1)

## 〇、测试策略

### 0.1 三层执行方式

| 层 | 工具 | 覆盖 | 说明 |
|----|------|------|------|
| L1 API 层 | curl / Python requests | 全部 95 端点可用性、权限矩阵、参数校验、状态码 | 快速确定性,先跑通打底 |
| L2 浏览器层(模拟人手) | Chrome 自动化(browser-use/Playwright):点击、填表、上传、截图 | 按业务流走完整 UI 路径,验证页面渲染/交互/提示 | 与人手操作等价,关键节点截图留证 |
| L3 数据核验 | API 交叉查询(必要时 SQL) | 闭环前后数据一致性(如:上传→列表→看板数字一致) | 防"界面显示对、库里不对" |

### 0.2 测试数据与账号约定

- 测试数据统一 `TEST-` 前缀(班级/学生/试卷/任务命名),结束后清理(删除 API 逐项回收)。
- 账号: 需要管理员与教师各一个(见待确认项)。教师账号同时用于验证数据隔离(只见本人任务)。
- 执行顺序: L1 冒烟 → L2 核心流(BF1→BF2→BF3→BF4→BF7→BF8→BF9) → L1/L2 扩展(BF5/BF6) → 清理。

### 0.3 已知断链项(预期失败,单独记录不判缺陷)

反馈(FeedbackForm/FeedbackList 无后端)、操作审计(audit 无端点)、旧 Vue SPA 全部页面(非生产前端)。
