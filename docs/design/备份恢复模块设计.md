## 0. 评审定案(相对 v1.0 的关键变更)

| 评审项 | 定案 |
|--------|------|
| DR-01(P0) | **恢复编排放独立 helper 脚本**,后端仅触发+轮询: `sudo systemd-run --unit=ai-restore-<id> --collect /bin/bash <repo>/scripts/restore_helper.sh <filename> <pre_backup:0/1> <restore_env:0/1> <restore_id>`;helper 写进度文件 `backups/restore_<id>.log`(每行 JSON step)+ 结束行 `{"step":"done","ok":bool}`;接口改**异步 202 {restore_id}** + 轮询 GET status |
| DR-02/05 | **单一全局锁** `backups/.lock`,`fcntl.flock`(进程死自动释放);备份/创建/恢复互斥;helper 内再次 flock 非阻塞探测 |
| DR-03 | program 包**排除 backend/.env**;.env 作为 **data 包的 env 部件**;恢复默认**跳过 .env**,`restore_env:true` 才覆盖(UI 红字提示"将使全部登录态失效") |

| DR-07 | 恢复后执行 `REASSIGN OWNED BY postgres TO ai_training` + `GRANT ALL ON ALL TABLES/SEQUENCES/FUNCTIONS IN SCHEMA public TO ai_training`;库无扩展,pg_dump 不含 CREATE EXTENSION(已核实) |
| DR-08 | 全部 subprocess 用**参数列表 + shell=False**;解包用 python tarfile,**filter="data"**(拒绝对象路径/..),部件总解压上限 2GB |
| DR-09 | create/restore 前 `shutil.disk_usage` 检查空闲 <2GB 拒绝 |
| DR-10 | jiaoyanyun 为按需脚本非常驻(已核实无 systemd 单元);恢复 data 后 steps 提示"教研云 Chrome/令牌如在使用请手动重启" |
| DR-11 | 路由一律无尾斜杠;删除"backups 加入 .gitignore"表述(backups 在 /opt 顶层,不在仓库内) |

## 1. 存储

- 目录 `/opt/ai-learning/backups/`(启动/调用时 ensure);锁文件 `backups/.lock`;进度 `backups/restore_<id>.log`
- 命名 `backup_(program|data|full)_[0-9_]{15}\.tar\.gz`(白名单正则,list/download/delete/restore 统一校验)

## 2. 包结构

```
backup_xxx.tar.gz
├── manifest.json         # 最后写入: {type, version, created_at, parts:[{name,sha256,bytes}], app:"ai-learning"}
├── program.tar.gz        # program/full: backend(排 venv/__pycache__/uploads/*.db/dev.db/.env)、
│                         #   frontend/src frontend/demo/index.html frontend/demo/api-bridge.js frontend/package.json frontend/vite.config.js、
│                         #   scripts、docs、tests、jiaoyanyun/*.py *.js、根 AGENTS.md CHANGELOG.md README.md VERSION cloud_migration.md .gitignore
├── db.sql.gz             # data/full: pg_dump --clean --if-exists --no-owner ai_training | gzip
├── env.tar.gz            # data/full: backend/.env
├── uploads.tar.gz        # data/full: uploads/ 全部
├── demo_images.tar.gz    # data/full: frontend/demo/images/
└── jcred.tar.gz          # data/full: jiaoyanyun_credentials.json + jiaoyanyun_token.json
```

## 3. 后端(backend/app/routers/backup.py,main.py 挂载,无尾斜杠)

| 端点 | 权限 | 语义 |
|------|------|------|
| GET `/api/v1/system/backup/list` | system:view | 扫描目录,校验 manifest 完整(缺/坏标注 damaged 不列入可恢复),返回 [{filename,type,version,created_at,size_bytes,damaged}] |
| POST `/api/v1/system/backup/create` body {type} | system:edit | flock→磁盘检查→按类型组装部件(subprocess 列表参数 shell=False,pg_dump 经 `sudo -u postgres`,超时 600s)→逐部件 sha256→**最后写 manifest**→失败清理半成品并释放锁 |
| GET `/api/v1/system/backup/download?filename=` | system:view | 白名单+存在校验→FileResponse |
| POST `/api/v1/system/backup/delete` body {filename} | system:edit | 白名单+存在校验→删除 |
| POST `/api/v1/system/restore` body {filename,confirm,pre_backup=true,restore_env=false} | system:edit | confirm 必须 true→磁盘检查→触发 systemd-run(202 {restore_id});confirm 非 true → 400 |
| GET `/api/v1/system/restore/status?restore_id=` | system:view | 读进度文件→{done,ok,steps[]} |

## 4. restore_helper.sh(仓库 scripts/,部署走 quick-sync)

输入: `<filename> <pre_backup> <restore_env> <restore_id>`;以 ubuntu 运行(root 权限经 sudo)。
流程(每步写进度行 JSON):
1. flock 探测 .lock(被占→失败退出)
2. pre_backup=1 → 先调本机备份逻辑生成 `backup_full_时间戳.tar.gz`(安全备份,记录文件名)
3. 解包校验(部件 sha256)
4. program 部件存在 → tar 解包覆盖 /opt/ai-learning(--overwrite;tarfile 由 helper 侧 shell 完成:`tar xzf program.tar.gz -C /opt/ai-learning --overwrite`;helper 中 tar 亦可用 --numeric-owner)
5. data 部件存在 → `sudo systemctl stop ai-learning` → psql 终止连接 → DROP/CREATE SCHEMA AUTHORIZATION ai_training → `gunzip -c db.sql.gz | sudo -u postgres psql -d ai_training` → REASSIGN OWNED + GRANTs → restore_env=1 则解 env.tar.gz 覆盖 backend/.env → 解包 uploads/demo_images 覆盖 → `sudo systemctl start ai-learning`
6. `trap 'systemctl start ai-learning 2>/dev/null || sudo systemctl start ai-learning' EXIT`(保证最终拉起)
7. curl 健康检查 127.0.0.1:8001/health(重试 10×3s)→ done 行 {ok}
运维约束(写进 UI 与本文): 恢复窗口内禁止 quick-sync/deploy。

## 5. 前端(demo SPA,route system.backup)

菜单「💾 备份与恢复」;页面: 三个创建卡片(程序/数据/整体,确认后创建,spinner)→ 列表表格(文件名/类型/版本/大小/时间/⬇下载 ♻恢复 🗑删除)→ 恢复模态(信息+红字警示+pre_backup 勾选默认开+restore_env 复选默认关+「我已知晓」勾选后才可点恢复)→ 恢复中轮询 status 展示 steps → 完成/失败展示;删除二次确认;非 admin(system:view 缺失)菜单不显示且路由守卫。
